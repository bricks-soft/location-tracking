## Public API traceability

[API coverage](ios-location-tracking-api-coverage.md) maps each of the 47 existing methods and 15 events to contracts, tests and stages. The seven proposed methods (precision, four session/capability methods, and two guarded subscription bridge methods) are separate. No method is counted by a substring match.

The existing pre-ready allowlist is `ready`, `getState`, `checkPermissions`, `requestPermissions`, `getDeviceInfo`, `getSensors`, `log`, `getLog`, `getProviderState`, `openBatteryOptimizationSettings`, `openPowerManagerSettings`, `openLocationSettings`, `openAppSettings`. The proposed capability/precision methods join it after approval. Session setup can run before ready under §4.3; context-owned methods require SessionGuard, including reads. Admission during cleanup is stricter than readiness. [P21](https://github.com/bricks-soft/location-tracking/blob/f1edfd6279965f581d46d7a3434fa93e3d515a2f/android/src/main/java/com/brickssoft/locationtracking/bridge/PluginHandlers.kt#L531).
