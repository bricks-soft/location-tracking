**Status: proposed, planning only. Yasser's explicit approval is required before any product or harness implementation or build.** Approval of this RFC must name any changed defaults. It does not authorize publishing a package, deployment, feature enablement, device action or store release. Those gates remain separate.

Proposal: add iOS support to the plugin and reuse the Android design decisions where the platform permits.

## 2. Outcome and boundaries

Implement a native iOS route engine behind the current `LocationTracking` API, with durable, authenticated delivery into Bricks. Preserve Android's product rules where possible: event identities and timestamps, configuration semantics, filtering, moving/stationary math, audit records, queue and retry policy. State iOS limitations explicitly where Apple controls scheduling or sensors.

Scope includes the plugin API, package delivery, native lifecycle, privacy resources, necessary Bricks driver/session/provider/gate integration, and narrow BE compatibility if provider status requires it. It excludes VisitMonitoring/auto-end, visit grace timers, Live Activities, push changes, general offline/product cleanup and any new paid service. A visit is only an integration trigger when the existing app requires tracking, not permission to redesign visit policy.

Host integration must satisfy three requirements:

- Cleanup must complete after failed or timed-out uploads, before another login or tenant can configure the plugin.
- Workday cutoff must follow an approved timezone and DST policy.
- An iOS cohort gate must precede native plugin adoption so availability alone cannot start a route.

### 4.1 Termination and heartbeat semantics

`app.stopOnTerminate:true` means **no automatic capture restore after a new process starts** on iOS. This is an explicit conservative adaptation: Android stops on task removal and can restore after an OS kill. iOS cannot reliably classify the cause of process loss. A new process detects an interrupted persisted intent, not whether a person force-quit it. Set intent off on recovery and record only the observation time, with a proposed `process_restart` stop reason. Never label the cause `user_stopped`, `terminate`, `boot` or jetsam without evidence.

If `applicationWillTerminate(_:)` arrives, do a bounded best-effort persistence of off intent when the flag is true. That callback is not guaranteed, is also possible for system termination, and cannot identify a user action. Do not wait for network cleanup there. With false, eligible events or foreground launch can restore valid intent after cleanup and deadline checks. Neither setting promises force-quit or boot delivery. [A21](https://developer.apple.com/documentation/uikit/uiapplicationdelegate/applicationwillterminate(_:)), [A8](https://developer.apple.com/documentation/foundation/urlsessionconfiguration/background(withidentifier:)).

`app.startOnBoot` has no iOS launch effect. Accept it as a documented platform no-op, logged at debug level once when applied. Do not append it to `State.warnings` on every `ready()`. Document the platform capability separately. It does not gate eligible iOS restore; explicit off, cleanup and cutoff still win.

The continuous profile starts location updates in foreground with the location background mode and `allowsBackgroundLocationUpdates=true`. A native `DispatchSourceTimer`, owned by the serial core, evaluates the same heartbeat window as Android while runnable. It queues at most one due record with the current creation time and the existing anchor's fix time. Stop cancels it. Suspension or process loss prevents evaluation; the next execution reports elapsed gaps and never synthesizes missed records. Timer execution grants no extra background runtime. Use `ios_location_timer` for live timer evaluation and `ios_opportunistic` for a due evaluation on a real callback or recovery. `next_at` is an estimate or null. Q1 and D08 determine whether its measured cost is acceptable. [A20](https://developer.apple.com/documentation/corelocation/cllocationmanager/allowsbackgroundlocationupdates).

### 4.2 Region adapter and fallback

Use the Swift `CLMonitor` actor on iOS 17+: `await CLMonitor(stableName)`, `CLMonitor.CircularGeographicCondition`, `await monitor.add(_:identifier:)`, `await monitor.remove(_:)`, and a retained task that iterates `monitor.events`. The initializer, circle type, add method and events property are available from iOS 17.0. Persist desired conditions and recreate the same monitor name on eligible launch. Consume events continuously; record unknown/unmonitored states separately from a confirmed ENTER/EXIT. A registration call alone is not a physical delivery result. [A18](https://developer.apple.com/documentation/corelocation/clmonitor-2r51v), [A19](https://developer.apple.com/documentation/corelocation/monitoring-the-user-s-proximity-to-geographic-regions).

Apple limits an app to **20 simultaneous conditions of any type**, not 20 per monitor. A host must coordinate its other condition owners; the plugin cannot enumerate an unknown monitor's conditions. Count declared reservations plus actual plugin registrations and surface OS registration failures. Do not remove another owner's conditions. The recommended profile needs zero internal slots. Q3 native-cap release rejects overflow with `TOO_MANY_GEOFENCES`; batch semantics match the approved public contract with per-item evidence. No silent virtualization.

A `CLLocationManager`/`CLCircularRegion` adapter is the compatibility fallback for iOS 15/16 if Q4 selects that floor, or an explicitly selected, qualified OS-specific workaround. It uses `startMonitoring(for:)`, delegate callbacks and `monitoredRegions`. Current Apple documentation marks this entry point deprecated at iOS 27.2; that metadata is not a claim about installed SDK availability. Do not silently switch adapters after a permission, capacity or transient error. Switch only after removing/reconciling this plugin's old registrations; never run both for one condition. Fallback has its own 20-region limit and no stronger wake guarantee. [A7](https://developer.apple.com/documentation/corelocation/cllocationmanager/startmonitoring(for:)).

After reboot, monitoring cannot occur before first unlock. Reconcile desired conditions on the next permitted execution; do not infer a boot launch. Reduced accuracy prevents region monitoring; expose a blocked state until an explicit precision request succeeds. Polygon and dwell calculations need actual execution and cannot promise a scheduled wake. [A5](https://developer.apple.com/documentation/corelocation/cllocationmanager/accuracyauthorization), [A19](https://developer.apple.com/documentation/corelocation/monitoring-the-user-s-proximity-to-geographic-regions).

Reduced precision is a capability loss, not a less accurate native fence. Under the selected region contract, `addGeofence(s)` and `startGeofences` reject `ACCURACY_REDUCED` before new registration; denied/restricted authorization rejects `PERMISSION_DENIED`, services off rejects `LOCATION_DISABLED`. Persist existing desired definitions, but remove or mark inactive every owned registration when capability is lost. Expose desired and active counts separately. On restored precision/services, reconcile desired definitions only if the current grant, mode, deadline and capacity remain valid. A failed or late registration cannot become active in a retired epoch. Never remove foreign regions. [A5](https://developer.apple.com/documentation/corelocation/cllocationmanager/accuracyauthorization).

Prevalidate a geofence batch and its capacity before mutation. Resolve success only after every requested registration succeeds. On an OS partial failure, roll back newly added owned registrations and retain the prior desired set; emit actual counts/errors. If rollback itself fails, expose reconciliation pending and block the next add/start until it settles. Per-item diagnostic evidence must show both initial successes and failures; the void-return API cannot imply partial success. T12 checks these boundaries. Polygon/dwell evaluation can continue only on real permitted fixes in an active location route, with observed entry time. A geofence-only blocked state has no wake mechanism. Do not invent transitions or dwell time missed during a gap.

A temporary `CLError.locationUnknown` means no fix now. Keep the valid subscription and show a transient locationerror; do not permanently disable intent. Authorization denial requires service shutdown and blocked status; restart only after an observed valid grant and live session. For an event stream that ends or throws, reconcile exactly one subscription on the next permitted opportunity with bounded retry/backoff and visible diagnostics. Never remain enabled with an irrecoverably dead subscription. Other errors must map to an explicit transient/blocked action at S0 rather than a generic silent retry. [A35](https://developer.apple.com/documentation/corelocation/clerror-swift.struct/code/locationunknown), [A36](https://developer.apple.com/documentation/corelocation/clerror-swift.struct/code/denied).

### 4.3 Proposed native activation and session protocol

**This is an additive proposal, absent from 8.1.0.** The existing API has `ready(options?)`, `setConfig({config})`, `start()` and `stop()`, with no activation, binding or logout operation. [P3](https://github.com/bricks-soft/location-tracking/blob/f1edfd6279965f581d46d7a3434fa93e3d515a2f/src/definitions.ts#L734). Approval includes new methods, optional argument fields, error codes and iOS semantics below. Android retains its existing behavior; new protocol methods reject `UNIMPLEMENTED` on Android/web. Do not pretend that current Android implements the native barrier. Shared host finally-cleanup changes require Android regression tests.

The host auth owner creates a random opaque `sessionId` per login, and an opaque `binding` for the authenticated user/workspace/login. Store both in its protected session metadata. Reuse them through token renewal and process restart. A new login, user or tenant must use new values after the old barrier. This binding is **local session metadata**, not an owner key on each point or a retained cross-user queue. The plugin does not authenticate arbitrary JavaScript or infer a person from a token. The trusted host must serialize its authenticated session stream and supply the right binding.

Proposed types (all timestamps below are ISO-8601 UTC with millisecond precision):

```ts
interface SessionGuard { sessionId: string; epoch: number; grantId: string }
interface ActivationGrant {
  grantId: string; protocolVersion: 1; policyRevision: string;
  purpose: 'route' | 'delivery_only';
  captureCutoffAt: string; deliveryExpiresAt: string;
}
interface SessionReceipt {
  session: SessionGuard; credentialRevision: number;
  cleanup: 'idle'; intent: 'off';
}
// Config/Authorization below are the existing public types.
// SessionGuard belongs to call/task metadata, never a queued record.
```

| Proposed entry point | Admission and durable effect | Result / exact refusal |
|---|---|---|
| `getTrackingCapabilities(): Promise<{protocolVersion:1; sessionRequired:true; epoch:number; transport:'ephemeral'; daemonUploads:false}>` | Pre-ready, context-free. Return the persisted installation epoch. It grants no collection or upload authority. | Unsupported native shell lacks the method; new web stays off. This is capability negotiation, not enrollment. |
| `activateTrackingSession({expectedEpoch:number, sessionId:string, binding:string, grant:ActivationGrant, credentialRevision:number, config:Config}): Promise<SessionReceipt>` | Foreground only, after cohort, supported BE, consent and auth checks. CAS against persisted epoch. Initial binding requires no live prior binding. Prepare an off-intent transaction, store Keychain credentials, then commit the active grant last. Capture still requires guarded start. | `INVALID_ARGUMENT` for malformed/expired dates, missing auth/binding/revision or invalid config; `SESSION_MISMATCH` for stale epoch/binding; `SESSION_CLEANUP_PENDING` while prepared/cleanup is unresolved; `PERMISSION_DENIED` in background; `IO_ERROR` on storage failure. No partial activation. |
| Same `activateTrackingSession` for the same login binding | Requires the current epoch, an off route, a new grantId and foreground host authorization. Increment epoch on every accepted grant; retain same-login queued points. Preserve the existing route cutoff on a purpose=delivery_only renewal; that grant cannot start capture. Same-login regrant is allowed only while intent is off and all live tasks are quiescent. It cannot race old admission. Close prior-grant watch/listener handles under §4.8 before returning the new receipt. Pending rows retain their UUIDs. A new workday cutoff requires a new explicitly authorized route, never automatic ready/reset. | Old guards become stale. An identical retry of the committed activation returns the same receipt; a changed payload under the same grantId rejects `INVALID_ARGUMENT`. Never replace a different binding. |
| `updateTrackingCredentials({session:SessionGuard, expectedRevision:number, revision:number, authorization:Authorization}): Promise<{credentialRevision:number}>` | Same binding only; compare epoch/grant and revision; revision must be exactly expectedRevision+1. Commit the secret and revision through a prepared transaction before new requests. Keep queued records, capture cutoff and intent. | `SESSION_MISMATCH`, `SESSION_CLEANUP_PENDING`, `INVALID_ARGUMENT` or `IO_ERROR`. A stale refresh cannot change the token. Existing requests keep their frozen older context; only later same-session attempts use the new revision. |
| `endTrackingSession({session:SessionGuard}): Promise<{cleanup:'idle'; epoch:number}>` | First native logout operation: transactionally persist intent off, revoke grant, increment epoch, and mark cleanup pending **before any await**. Close all acquisition/upload/refresh admission. Cancel own live tasks; fence callbacks; purge queue, context state and Keychain secrets; commit clean last. | Resolve only after cleanup and task quiescence. On `IO_ERROR` or protected-data failure remain durably pending; `SESSION_CLEANUP_PENDING` exposes unfinished cleanup. A repeated end of the same retired session is idempotent and cannot affect a newer one. `SESSION_MISMATCH` rejects any other stale end. |

The installation epoch is monotonic and survives clear/reset; reset cannot turn it back to zero. A fresh installation has no grant. Activation is a host integration boundary, not a new authentication endpoint or a server feature-flag authority. Proposed hard lifetime: `deliveryExpiresAt` is at most 24 elapsed hours after foreground grant validation; captureCutoffAt cannot exceed that lease. For **either Q2 option**, the host stores the selected civil cutoff but passes captureCutoffAt=min(civil cutoff, lease expiry); the generic elapsed maximum can stop it earlier again. A DST or device-local policy that selects more than 24 hours is explicitly lease-capped, with the earlier stop shown to the user. A longer route requires an amended, approved lease policy; no silent extension is permitted. Persist both instants and the monotonic expiry. After cutoff, earlier points can replay within the valid delivery lease. After lease expiry, keep rows blocked until same-login foreground validation renews delivery, or logout purges them. A web-only cohort revocation reaches native through guarded stop/end at its next execution; headless native cannot know an unseen remote flag. The 24-hour cap bounds an unrenewed grant. Yasser must approve this limit and conservative uncertain-clock rule.

**Existing-call compatibility:** add `session?: SessionGuard` to existing option objects. Methods with no options gain optional `{session?: SessionGuard}`. `watchPosition` keeps its callback argument. `addListener` uses the plugin-owned wrapper in §4.8; Capacitor's built-in native listener proxy cannot forward a third argument. Each watch captures its guard from its normal callback-method options. These are optional at the shared TypeScript boundary for legacy Android callers, but mandatory on iOS for context-owned calls. This includes ready, config/reset, start/stop/changePace, queue/odometer/geofence/log reads and writes, sync, state with context, watches and listeners. Auth-bearing `setConfig` or reset can repeat byte-identical current credentials, but cannot replace them: use `updateTrackingCredentials`. An ordinary current-guard ready/reset cannot extend or rebind a grant, rewind the epoch, or move a cutoff. The explicit end aliases below instead revoke authority and increment the epoch through the same tombstone transaction. A validated `authorization:null` or reset-to-defaults with a current guard invokes the same end barrier, as a safety alias. New non-null auth or tenant/URL/header/template changes require session protocol revalidation; they cannot silently rebind retained rows. Invalid input has no side effects.

Unbound context-free `getState` returns only off/empty capability state; permission/device/sensor/public-settings calls remain available before ready. Unbound foreground `getCurrentPosition` requires explicit `persist:false` and never stores a shared cached fix. All other context reads return `SESSION_REQUIRED` without a guard. A missing guard on an activating call returns `SESSION_REQUIRED` and starts revocation/cleanup of a persisted grant, if present. A mismatched guard returns `SESSION_MISMATCH` without mutating the current session. Thus the actual old bundle's ready/start/setConfig/startGeofences/changePace calls cannot create authority or read old queued data on a new binary. A late unfenced call is conservatively treated as an incompatible bundle, so it can disable capture but cannot enable it. Missing guard is distinct from a stale guarded A operation, which cannot stop B.

On first adoption, the new binary has no grant even if it reads legacy config. A cached/rolled-back old bundle stays off. If a previously approved grant restores headlessly before an incompatible bundle attaches, it can act only within its persisted lease and cutoff. The first incompatible activating call revokes it. There is no claim that native sees an OTA rollback before JS or a flag update runs. T14 uses the exact pinned old bundle calls and also the persisted-grant rollback case.

**Logout linearization and recovery:** host first durably writes its cleanup-pending marker, without removing FE auth. It then calls `endTrackingSession` immediately. Do not await a logout flush first. The proposed logout path discards unsent points; an explicit stop/sync before logout is separate and cannot postpone the barrier. The native tombstone commit is the linearization point: requests already issued remain A; after it no A admission occurs. FE token removal, new-login UI completion and B activation wait for the end receipt. On host timeout keep pending; timeout is not cancellation. A headless launch resumes native pending cleanup before restore; a crash before native commit resumes the host marker before binding any new login. No cross-store atomicity is claimed.

`cancel()` returns immediately; `didCompleteWithError` and even a raced response can arrive later. Yield the serial owner while waiting. Reconcile `getAllTasks` for the plugin's live ephemeral session, and require terminal callbacks or confirmed absence after invalidation/reconciliation. In a new process an ephemeral task cannot reconnect as a daemon task: clear its old in-flight map only after the old process boundary is established, retaining unacknowledged rows. No loop waits for an old daemon callback. Stale completion can retire only its own bookkeeping; it cannot emit B success, retry, delete B rows or write refreshed credentials. [A22](https://developer.apple.com/documentation/foundation/urlsessiontask/cancel()), [A24](https://developer.apple.com/documentation/foundation/urlsessiontaskdelegate/urlsession(_:task:didcompletewitherror:)), [A25](https://developer.apple.com/documentation/foundation/urlsession/getalltasks(completionhandler:)). A nil completion error still needs an HTTP status check. Cancellation cannot retract an already accepted A write.

Crash points are required after: host marker; native prepare/tombstone; Keychain write/delete; task cancellation request; terminal callback; each queue/runtime/config purge; SQLite clean commit; FE token removal. Prepared or inconsistent SQLite/Keychain metadata blocks capture and sending. Recovery finishes cleanup rather than reconstructing an old secret. A Keychain item without its installation/session marker is an orphan and must be removed before activation, including after reinstall/backup restore. T08/T09 require failures at each boundary and context canaries from §4.7.

### 4.5 Persistence, identity and upload recovery

Use system SQLite with transactions, WAL and explicit schema migrations. Create the database and log directories with `NSFileProtectionCompleteUntilFirstUserAuthentication` before creating files. Apply and inspect the protection on existing files during migration, including `.db`, `-wal`, `-shm` and logs, plus any temporary file later introduced. Set backup exclusion on all of them; test after checkpoint/reopen and side-file recreation. Do not assume directory inheritance without checking the resulting attributes. Before first unlock, defer safely rather than change protection. Use `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`, non-synchronizing Keychain items for secrets. Cleanup remains pending if protected storage cannot be accessed. [A26](https://developer.apple.com/documentation/foundation/fileprotectiontype/completeuntilfirstuserauthentication), [A27](https://developer.apple.com/documentation/security/ksecattraccessibleafterfirstunlockthisdeviceonly).

Read `UIDevice.current.identifierForVendor` natively for `device.device_id`; the record factory never waits for a JavaScript bridge. Capacitor Device uses the same source, but is not a runtime dependency. If nil, omit the unavailable field for that record and re-read after first unlock and on later records; do not cache nil for the process. Never mint a substitute or rewrite a queued record's identity. IDFV can change after all vendor apps are removed or with test/ad-hoc installs. R3-Q7 leaves future cross-platform normalization open: confirm IDFV as the initial iOS value, without claiming the later normalization is implemented. [A28](https://developer.apple.com/documentation/uikit/uidevice/identifierforvendor), [P4](https://github.com/bricks-soft/location-tracking/blob/f1edfd6279965f581d46d7a3434fa93e3d515a2f/docs/DECISIONS.md#L711).

The uploader persists logical-attempt metadata (UUIDs, frozen context hash/revision, request time, state) before resuming a suspended ephemeral task. Keep the task association in memory and durable metadata for crash diagnosis; tasks do not survive as reconnectable daemon transfers. On process recovery abandon the old in-flight attempt and retry still-unacknowledged rows. A crash after BE commit but before local deletion repeats the stable UUID. Queue rows have no owner field. Same-session credentials can advance only through §4.3; a different binding purges first. Priorities can bypass a poison ordinary record, so HTTP order is not globally chronological. [P8](https://github.com/bricks-soft/location-tracking/blob/f1edfd6279965f581d46d7a3434fa93e3d515a2f/android/src/main/java/com/brickssoft/locationtracking/data/SqliteLocationStore.kt#L18), [P9](https://github.com/bricks-soft/location-tracking/blob/f1edfd6279965f581d46d7a3434fa93e3d515a2f/android/src/main/java/com/brickssoft/locationtracking/http/OkHttpSyncer.kt#L46).

### 4.6 Permitted-execution upload contract

Select a dedicated **ephemeral URLSession** for the first release. It can send in foreground or while an authorized background mode gives the app execution. Refuse every 301/302/303/307/308 redirect in `willPerformHTTPRedirection` by completing with nil. Treat 3xx as unacknowledged; do not follow same-origin or cross-origin destinations. Disable shared cookies, cookie storage, credential storage, cache and ambient auth challenge credentials. Only the frozen request's explicit auth is allowed. Require normal platform TLS trust and ATS in the host. [A33](https://developer.apple.com/documentation/foundation/urlsessiontaskdelegate/urlsession(_:task:willperformhttpredirection:newrequest:completionhandler:)), [A34](https://developer.apple.com/documentation/foundation/downloading-files-in-the-background).

At each logical attempt, freeze URL, method, body/template, params, headers, tenant, binding epoch and credential revision before resume. `sent_at` means **attempt construction time**, not socket transmission or server receipt. Preserve creation/fix times and UUID. A later retry gets a new sent_at and can use a newer credential revision only within the same login binding; it cannot mutate an existing attempt. Log all observed exchanges separately from logical retries. A generic target 200 never acknowledges the original endpoint. T06 uses the real production URLSession adapter and destination logs, including a redirect-to-200 sink that stores nothing.

Set finite request/resource timeouts, response-body bounds and concurrency limits in S0 before target tests; record them as fixture inputs. A response over the approved limit fails and retains rows. On execution expiry, close admission, cancel tasks and persist retry state; if suspension prevents completion, recovery repeats unacknowledged UUIDs. No autonomous upload deadline or continued transfer while suspended is promised. Use bounded in-memory request bodies for the approved batch limit; no upload spool file is required in this design. If any temporary file is introduced, its size/protection/backup/purge rules must be frozen and tested first.

A **background URLSession daemon is deferred**, not an interchangeable optimization: Apple follows redirects there and restricts interception, custom protocols and uploads. It can also retain a system copy of an upload file. A final URL check cannot undo an already sent route. Retaining that option requires a separately amended redirect/auth/privacy/cancellation/acknowledgement contract and focused review before implementation. URLProtocol or an app fake cannot prove a daemon's no-redirect behavior. Existing host background downloads are a separate feature and remain intact.

### 4.7 Account state and server acceptance requirements

A session barrier clears queue, cached last fix, motion anchor, odometer, geofence desired/active state and extras, context config/URLs/headers/params, log content, watches, listener handles and pending callback values. Keep only app-owned platform defaults, schema/installation metadata and the monotonic epoch; these must contain no route or principal data. Watch/listener callbacks check their guard again immediately before emission. During cleanup context reads reject SESSION_CLEANUP_PENDING; after it unbound reads are empty or SESSION_REQUIRED. A-only canaries must never appear in B local reads, callbacks or crash telemetry. T09/T13 cover every surface plus cleanup failures and orphan Keychain items after reinstall/backup. Local purge does not erase accepted server history.

The enabling backend must support explicit top-level `corelocation` provider fields and status calculations before the iOS cohort starts. **Old BE is unsupported for accurate iOS provider status.** Omitting a snapshot can retain an earlier Android blocked/unblocked snapshot; raw_event cannot repair authoritative state. Do not enable on old BE through an omission fallback. Support matrix: old client/new BE remains compatible; new iOS/new qualified BE can enable; new iOS/old or rolled-back BE stays off and any already-active client stops at its next validated execution or lease expiry. Record the exact enabling deployment and capabilities. No source pin proves deployment. T11/T15 seed both prior Android states, a new user, device transitions, delayed Android replay and revoked iOS permissions.

Row deduplication and derived-state acceptance are separate requirements. The **proposed** narrow receiving-service contract is below; it is not a claim about an existing BE API. It requires a separate scoped dependency and approval before S5. If the owner declines the remedy, S5 stays blocked until an explicit alternative limitation and matching oracles replace it. Preserve Android emitted records/config and ordinary ingestion behavior. Exceptional conflict/skew/status corrections are explicit compatibility deltas, requiring separate maintainer approval and Android regression tests before adoption. If they cannot preserve the approved support matrix, S5 remains blocked. Do not extract behavioral fields from raw_event.

- Accept rows and state atomically. A new unique event gets a durable server acceptance sequence. An identical retry under the same authenticated principal changes no row or derived snapshot. A conflicting payload for that UUID returns 409 and leaves the whole submitted transaction unchanged. The canonical payload comparison excludes attempt sent_at/receipt metadata; creation time, fix, event, provider and identity must match.
- Within a tenant, an event UUID already owned by another user returns a non-disclosing conflict; never relabel the row or mutate the caller's state. A separate tenant can use the same synthetic UUID independently. Pin actual database uniqueness scope and auth/tenant middleware before declaring compatibility.
- Choose lastRecord/provider by (effective creation time, original acceptance sequence); choose last fix by (capture time, effective creation time, original acceptance sequence). A duplicate retains its first sequence. Thus equal-time start A, stop B, replay A leaves stop B current. Priority bypass and separate batches cannot change this result. No-fix audits leave last fix unchanged.
- Proposed future-time tolerance is 5 minutes relative to authenticated server receipt. A creation or capture time beyond it returns 422 for the transaction, with a clock-skew error and no state/row mutation. Client retains rows and blocks that retry for explicit clock recovery; it must not rewrite them. Within tolerance, preserve original times on the row but cap effective creation time at receipt time for status. Online requires a nonnegative age within the configured timeout; a future value must not hold a user online indefinitely. Corrected current records can advance state. Past/delayed records remain valid history but cannot displace a later effective state. T15 fixes exact examples.
- State-patch or commit failure returns non-2xx and rolls back rows plus snapshots. An acknowledgement after a lost response can repeat safely. Characterize malformed-item 2xx-drop separately with DB readback; never use that legacy behavior as a general storage guarantee.

Recipient authorization is a release dependency. Proposed policy: a manager with the required route scope can read only the users that the manager is authorized to manage in that tenant; self access requires its separately approved scope. Test route-by-user-ID, trackable/user-state reads, daily statistics and exports through real HTTP auth and tenant middleware. Another manager's user, an unpermitted user and another tenant must not receive route/status data. S0 must pin real scope identifiers and actual consumers in the receiving repositories; TBD policy or an unresolved reader gate blocks S5/S6 and final consent wording. A repository TODO alone is not proof of a deployed bypass. Any necessary permission remedy is a separate narrow dependency.

### 4.8 Guarded subscriptions through a plugin-owned wrapper

**Proposed, absent at the pin.** Capacitor 8.5.2 and the inspected 7.4.3 runtime special-case native `addListener(eventName, callback)`: only `{eventName}` reaches native. They drop a third options argument. The plugin currently exports the raw proxy and its `on` helpers call that proxy. Therefore adding a TypeScript overload alone cannot carry a SessionGuard. [K3](https://github.com/ionic-team/capacitor/blob/8.5.2/core/src/runtime.ts), [P22](https://github.com/bricks-soft/location-tracking/blob/f1edfd6279965f581d46d7a3434fa93e3d515a2f/src/plugin.ts#L1), [P23](https://github.com/bricks-soft/location-tracking/blob/f1edfd6279965f581d46d7a3434fa93e3d515a2f/src/events.ts#L55).

Select a plugin-owned `src/plugin.ts` wrapper. Keep the registered raw proxy module-private. On Android/web, `addListener` and removal delegate unchanged to the current two-argument path. On iOS, the exported `addListener(eventName, listenerFunc, {session})` freezes the caller's guard and a fresh opaque subscriptionId **synchronously at invocation**, before any lazy load or await. It never reads a newer global guard to reclassify an old request. Missing guard rejects SESSION_REQUIRED. Add optional `{session}` to every standalone `on`/`onLocation`/other `on*` helper and route them through this wrapper. Update definitions, web/e2e mirrors, package exports, docgen and tests together. New low-level methods reject UNIMPLEMENTED on Android/web and never replace their existing listener route.

| New native bridge method (proposed) | Transport and exact lifecycle |
|---|---|
| `subscribe({eventName:LocationTrackingEventName, session:SessionGuard, subscriptionId:string}, callback:SubscriptionCallback): Promise<CallbackID>` | A **callback-type** Capacitor method, not the reserved addListener proxy. Its options reach native. Validate event name, current guard and cleanup state on the serial owner before saving a call. Missing/stale guard reports SESSION_REQUIRED/SESSION_MISMATCH through the error callback exactly once and releases the native call. A valid call enters a saved-call registry keyed by guard, eventName, subscriptionId and the bridge-assigned callbackId. KeepAlive ownership belongs to this registry. |
| `unsubscribe({eventName:LocationTrackingEventName, session:SessionGuard, subscriptionId:string, callbackId:CallbackID}): Promise<void>` | A promise-type method. Remove only the exact registry tuple and release that saved call, then acknowledge. A repeated removal of an already absent tuple is safe. A tuple colliding with a current call under a different guard rejects SESSION_MISMATCH; it cannot remove B. An A removal can retire only A bookkeeping, even after B activates. If unsubscribe arrives before admission, persist an in-memory cancellation tombstone for that guard/subscriptionId; a later subscribe for it rejects UNAVAILABLE and saves no call. Retain cancelled IDs until that epoch is retired; IDs cannot be reused. Do not call the built-in removeListener for a guarded subscription. |

`SubscriptionCallback` receives an internal discriminated envelope: `ready` carries subscriptionId and native callbackId; `event` carries those IDs, the captured SessionGuard, eventName and the existing typed event payload; `closed` carries subscriptionId and a reason (`removed`, `session_ended` or `registration_timeout`). It also has the usual optional `{code,message}` error argument. The wrapper removes this envelope before it calls the existing typed listenerFunc, so public event payloads do not change. Callback-type return of a callbackId alone is not proof of native admission: the exported addListener promise resolves a PluginListenerHandle **only after both that ID and matching ready arrive**. Error before ready rejects it; no payload is forwarded before readiness. Use a proposed configurable registration timeout, initially 10 seconds of permitted execution, for a call that has not emitted ready. S0 freezes the actual value before acceptance tests and qualifies it on minimum/current runtimes. This is application policy, not an Apple or Capacitor limit. A suspended JS timer cannot establish native cleanup.

`handle.remove()` sets its local closed gate immediately, then awaits unsubscribe acknowledgement and native saved-call release. Repeated remove calls share one completion. Preserve the deprecated promise.remove compatibility path through this same cleanup operation: if removal arrives before ready/ID, mark it closed, obtain/reconcile the callbackId, unsubscribe, then resolve an inert handle; native refusal still rejects registration. The wrapper never forwards payload after its local closed gate. `removeAllListeners({session})` is an explicit guarded native method that drains only the matching current registry; unguarded/raw removeAllListeners rejects SESSION_REQUIRED and stale A cannot remove B. Stop keeps current-session listeners long enough to report its committed off transition; end invalidates all old listeners and watches.

At end tombstone commit, block new subscriptions, close every A entry and release its saved native call, even with no JS. Host end invocation closes A's wrapper delivery gates synchronously before its first await. The wrapper rechecks its captured guard against the validated active host session immediately before every callback delivery, including envelopes queued before native cancellation. An already-issued bridge message cannot be retracted; its A envelope must be discarded after the host boundary, never re-labelled B. Activation updates the wrapper's validated generation before new subscriptions. Native companion listeners follow the same session boundary.

**Raw/legacy bypass is closed natively:** override/refuse iOS built-in `addListener` with SESSION_REQUIRED for all 15 tracking events; save no callback. Keep these payloads off unguarded `notifyListeners` entirely. Raw built-in removeListener/removeAllListeners cannot reach the separate guarded registry. Only admitted saved `subscribe` calls receive sensitive payloads. Stamping the current epoch when an unguarded request arrives is insufficient: a delayed A registration could then become B. A direct low-level guarded consumer must apply the same envelope/dispatch checks; it is a bridge mechanism for the wrapper, not a replacement application listener API. T01/T09/T14 test the raw proxy and native emission boundary, not just wrapper mocks.

Required races: delay A subscribe until B is active (native rejects stale guard, no saved call); register A then end before ready (wrapper never forwards and both native/JS handles close); delay A unsubscribe/removeAll until B has an identically named event (B remains registered); queue an A envelope before end but deliver it after B (wrapper drops it); remove before ready, duplicate remove, failed registration, registration timeout and reload/process loss (saved-call registry returns to its expected size). Exercise the actual Capacitor 8.5.2/7.4.3 proxy argument shapes with a native-header shim, then real iOS bridge callbacks. Count native saved calls and JS callbacks independently. No passing mocked addListener overload can close this gate.

## 5. Lifecycle state machine and invariants

The state is a product of persisted intent, actual execution, authorization, motion and upload state. A single enabled boolean cannot prove active collection or delivery. Execution states such as suspended/no-process describe OS reality for design and tests; the app cannot emit a callback that proves its own absent execution.

| Dimension | States | Stored / transient |
|---|---|---|
| Intent | off, enabled(session+mode+cutoff), logout-pending tombstone | Durable |
| Execution | uninitialized, ready, foreground, background-active, suspended, no-process, blocked | Actual OS state; recovered on launch, never inferred as perpetual from enabled |
| Motion | unknown, stationary(anchor), moving | Durable anchor and captured timestamp; transient pending timers |
| Delivery | empty, queued, in-flight(task map), retry-wait, auth-blocked, protected-data-blocked | Durable queue/retry/attempt metadata; ephemeral tasks abandoned on process recovery |

| Event | Precondition / transition | Required effects and UI truth |
|---|---|---|
| activateTrackingSession, then guarded ready | Foreground auth owner, cohort and qualified BE; current epoch; no pending cleanup. | Commit binding/grant safely, then config; no implicit tracking intent. Unguarded legacy ready cannot grant authority. |
| start in foreground | Current SessionGuard, unexpired capture grant, cohort on, eligible role/settings, consent and required authorization. | Persist session/deadline and start audit before subscription; start selected adapter; expose requested and actual state separately. |
| location/motion | Correct generation, still enabled, before cutoff, allowed services. | Filter; update motion/odometer; commit records before durable-receipt claim; emit and schedule upload. |
| enter stationary | Moving evidence absent for stopTimeout. | Persist anchor and motionchange; use Q1 power profile; no timestamp rewrite to pretend old anchor is fresh. |
| background/lock | Existing authorized route. | Native handles callbacks; no JS timers. UI at next foreground shows latest actual state and last delivery. |
| OS suspend/no process | OS-controlled; cannot run an app transition at the event time. | No invented tracking_stop, heartbeat or exact timestamp. Server detects silence; persisted intent remains subject to next-launch checks. |
| eligible OS wake / foreground launch | Valid intent, same session, consent/auth/cutoff still valid. | Create core without WebView; reconcile attempts, check grant/cutoff, restore adapter once; emit actual recovery audit without claiming boot cause unless known. |
| permission/services loss | Applicable callback or next wake reveals block. | Stop collection or degrade as allowed; queue provider audit; show blocked/limited. Foreground action needed for prompts. |
| cutoff reached | Timer while runnable OR any later callback/launch. | Persist off once; stop subscriptions; reject newly captured post-cutoff fixes. Keep earlier records for replay. No exact suspended callback promise. |
| explicit stop | User intent wins over queued start and OS wake. | Persist off before cancellation; audit once; remove registrations; upload already captured records per auth/session. |
| logout/tenant change | New context cannot activate before old barrier. | Use §4.3: host marker, immediate endTrackingSession tombstone, cancellation/purge, receipt, then FE token removal/new context. |
| app update/reboot/first unlock | No autonomous boot SLA. | On next permitted execution reconcile/migrate, honor stop/deadline/tombstone, restore only valid intent. A new install never starts old-user tracking from restored config. |

Invariants: one engine mutation at a time; one upload coordinator; no post-stop capture; record identity/time immutable through retries; no old record sent using new user/tenant context; a stale completion cannot mutate current auth/state; no background prompt; no claim of durable storage on failure; no synthetic heartbeat backfill; no OS trigger overrides explicit off/logout/cutoff. Tests must assert both state and side effects, including database and actual requests.

## 9. Integration, opt-in and rollback controls

1. Land a default-off iOS cohort/capability gate before adding the native plugin. Require cohort, consent, qualified BE and the §4.3 native grant with matching protocol versions. Old web cannot create a grant. Keep location verification policy separate from route enablement.

2. Keep Android emitted config/selection unchanged. Reuse the host driver and upload template; branch only the platform-specific permission/provider/heartbeat/lifecycle behavior. Handle absent plugins/old shells without background availability claims.
3. Session boundary is native as well as web. The exact §4.3 protocol runs immediately on logout, without waiting for a flush; old tasks cannot retry with new headers/token. Reconcile pending logout before any restore. For an access-token-only host, refresh integration requires an actual token-change event, not a guessed endpoint.
4. The server must attribute accepted records from its authenticated user and tenant context. Validate deployed candidate identity and schema read-only before stage trials. Preserve duplicate suppression and the exact accepted-state ordering contract. Require corelocation DTO/status and §4.7 replay/clock acceptance; old BE remains off for iOS. No assumption that a master pin is deployed. The qualified BE must precede the exact cohort-enabling deployment; old-BE rollback stops enrollment and blocks its status claim.
5. pilot tenant future trial uses explicit opt-in QA account(s), existing authorized access, synthetic fixture data and a dedicated approved public test route. Record cohort and data-retention plan. No production enabling in this task. Do not reuse personal/home tracks.
6. Rollback sequence: disable cohort start; issue native stop/clear on next allowed execution; ensure bounded session cutoff protects absent clients; cancel/reconcile own task namespace; retain BE duplicate support and accepted data; ship a compatible native rollback/hotfix if required. Do not rely on OTA web rollback alone, erase server rows, or downgrade incompatible SQLite schema.
7. Stop expansion on any cross-user/tenant upload, off-duty capture, unexpected auto-enable, unreconciled data loss, privacy leak, crash loop or failed agreed energy/fidelity budget. Rollback and evidence preservation require an assigned owner; no automatic deploy or force action inferred.

## 10. Evidence and review deliverables

The [validation matrix](ios-location-tracking-validation.md) defines reusable harnesses, deterministic fixtures, exact future command recipes, crash windows, simulator/hardware split and required evidence record. A result must identify source pin, package/build hashes, actual runtime, fixture, command/steps, UTC times and skew, expected/observed outcomes and artifact hash. For every claimed delivery, join a synthetic UUID from native persistence to HTTP receipt to stored BE row/state. Exclude secrets and home coordinates.

Yasser must approve the decisions, named API changes and platform adaptations before product or harness implementation or build. The contract matrix and API map are acceptance requirements, not completed results.

Implementation reviewers assess the final diff plus invariant fixtures; release reviewers assess actual tarball/app/native/web/BE pins and runtime evidence. Fixes require fresh affected checks. Final upstream signoff must explicitly accept iOS scheduling/termination limitations, privacy text, supported interface/capacity and remaining qualification gaps. No release happens automatically after a green suite.
