## Deterministic harness structure

Proposed Swift protocols: WallClock, ContinuousClock, Scheduler, LocationSource, MotionSource, PermissionSource, ConnectivitySource, CredentialsStore, RecordStore, Transport and EventSink. Production adapters use Apple APIs; tests inject scripted sources. The pure engine must not call Date(), network, Keychain or CLLocationManager directly. An isolated serial executor owns transitions. CLLocationManager callbacks enter via the main thread and carry a capture generation. Tests drain explicitly scheduled work rather than sleep.

Fixtures record `case_id`, source/expected-contract revision, config, wall and monotonic starts, input sequence, expected records/events/state/request/queue counts, and the intentionally different platform result. Freeze UUID/random generators. Normalize numeric tolerance and key order only; never normalize away UUID changes, field omission/null differences or lost timestamps. Separate pure policy fixtures from OS qualification results. Do not regenerate goldens from the implementation under test.

Use real SQLite files in temp directories. Kill a subprocess at named failpoints and reopen the same files. URLProtocol covers deterministic policy only. A real HTTP fault server and the selected production ephemeral URLSession must cover redirect refusal, frozen context, TLS and duplicate receipts. No background daemon is selected; mocks cannot qualify one. XCTest/Swift tests exercise logic; XCUITest/Appium exercises bridge and UI; physical tests establish OS/power facts.

## Decisive oracle controls

All cases here are future designs. `wire_attempts` counts every request/exchange observed by the server. `accepted_ids` comes from actual durable storage with authenticated principal and tenant. `derived_state` is the full persisted/status readback. Node `unique:true` is only a convenience view and cannot prove persistence deduplication. Logical retry attempts are separate from lower-level transport exchanges; an exact two-request assertion is permitted only with the deterministic fake transport.

The Bricks adapter must parse the explicit `locations` array with top-level `event_id` and `event`; do not treat nested raw_event as authoritative. Preserve the existing raw-plugin mode unchanged for Android fixtures. Commit-then-drop must wait for durable DB transaction acceptance before dropping the response. Drop-before-store is a separate fault and oracle. Store opaque tenant and credential aliases beside each attempt before redaction; fail a missing/mismatched tenant-header assertion.

Each decisive claim needs both its good fixture and a deliberate failing-control receipt. Corrupt event_id/template, substitute a tenant or credential alias, delete before acknowledgement, retry with a new UUID, suppress the upload, and duplicate actual acceptance. Each must fail its corresponding identity/isolation/ack/loss/dedupe assertion. If an injected defect still passes, the oracle is invalid. Freeze expected outputs independently of implementation code. Preserve failed attempts; never edit a golden to match a candidate.
